### Explaining the Print Permissions Chunk

Let’s break down the meaning of this code:

```cpp
std::cout << "Owner: "
    << ((p & fs::perms::owner_read)  != fs::perms::none ? "r" : "-")
    << ((p & fs::perms::owner_write) != fs::perms::none ? "w" : "-")
    << ((p & fs::perms::owner_exec)  != fs::perms::none ? "x" : "-")
    << ", Group: "
    << ((p & fs::perms::group_read)  != fs::perms::none ? "r" : "-")
    << ((p & fs::perms::group_write) != fs::perms::none ? "w" : "-")
    << ((p & fs::perms::group_exec)  != fs::perms::none ? "x" : "-")
    << ", Others: "
    << ((p & fs::perms::others_read)  != fs::perms::none ? "r" : "-")
    << ((p & fs::perms::others_write) != fs::perms::none ? "w" : "-")
    << ((p & fs::perms::others_exec)  != fs::perms::none ? "x" : "-")
    << std::endl;
```

#### What Does It Do?
- It prints **file permissions** for owner, group, and others in a style similar to `ls -l` output on Unix systems (like `rwxr-xr--`).
- The `p` variable holds permission bits for a file, retrieved with `fs::status(path).permissions()`.

#### How Are Permissions Checked?
- Each check uses:
    - Bitwise **AND** (`&`) between the permission bits (`p`) and a constant like `fs::perms::owner_read`.
    - If the result is not `fs::perms::none`, it means that permission is present.
    - The ternary (`... ? "r" : "-"`) prints `r`, `w`, or `x` if present, otherwise `-` if not.

#### Example Output Breakdown
If a file is regular, readable and writable by owner, readable by group, not executable:

```
Owner: rw- Group: r-- Others: ---
```
- **Owner:**
    - `r` if readable
    - `w` if writable
    - `x` if executable
    - `-` if not
- **Group/Others:**
    - Same logic for their respective rights

#### Why All This Logic?
- C++ filesystem permissions are stored as a set of bits (each representing read, write, exec for each category), see [cppreference].[2][5]
- Bitwise operations let you test exactly which rights are granted in one line for each permission (avoids manually decoding integers).
- The output is human-friendly, not just numbers![5][2]

##### In summary: This chunk builds a 3-block summary of file permissions using bitwise checks to display readable (`r`), writable (`w`), executable (`x`) rights for owner, group, and others, `-` if missing.
